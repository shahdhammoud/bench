# bench

> A benchmark dataset generator for testing and improving AI code reviewer agents.

## What is this?

`bench` is a research tool that builds a structured benchmark dataset to evaluate an AI code reviewer agent — a system that analyzes Python code against documentation to find bugs.

Each benchmark entry contains:
- **Gold code** — correct Python code taken from [SWE-Bench Verified](https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified) (real GitHub bug fixes)
- **Buggy code** — the gold code with a deliberate, realistic bug injected into it
- **Documentation** — auto-generated by the LangGraph doc generator for the task
- **Injection record** — a JSON object describing exactly what was changed, where, and which problem type it targets

The benchmark targets problem types the agent currently fails to catch, based on analysis of human code review traces.

## How It Works

### Doc Generator

A LangGraph workflow with 6 steps:

1. `inspect_files` — reads the target Python file(s)
2. `identify_contracts` — identifies interfaces and contracts
3. `infer_requirements` — infers functional and non-functional requirements
4. `generate_module_docs` — produces structured JSON documentation
5. `run_critic` — scores the documentation (0–10)
6. `fix_docs` — rewrites low-scoring docs; loops back to critic up to 3 times

Uses `PydanticOutputParser` with `get_format_instructions()` for structured output.

### Injectors

**Rule-based injectors** use AST parsing to make deterministic changes (e.g. replace `except ValueError` with `except Exception`).

**LLM-based injectors** use self-consistency: the LLM is called 3 times, return statements are extracted from each response, and the most common result (via `Counter.most_common()`) is used.

### Assembly Pipeline

`assemble_benchmark.py` automates the full pipeline:
1. Takes a SWE-Bench task → clones the repo, checks out base commit, applies gold patch
2. Runs the doc generator on the gold code
3. Runs 1–5 injectors to produce buggy versions
4. Saves each as one JSON entry in `benchmark.json`

Entries where `injected == false` (injector found nothing to change) are skipped automatically.

## Benchmark Entry Format

```json
{
  "task_id": "astropy__astropy-12345",
  "repo": "astropy/astropy",
  "file": "astropy/modeling/separable.py",
  "gold_code": "...",
  "buggy_code": "...",
  "documentation": { ... },
  "injections": [
    {
      "type": 7,
      "description": "Replaced specific exception handler with broad Exception",
      "location": "line 282",
      "injected": true
    }
  ],
  "critic_score": 7.5
}
```

## Quality Gates

- Entries scoring below **6.5** on the critic are removed
- Entries where gold code and buggy code are identical are removed
- All entries verified: zero identical gold/buggy pairs

## Known Gaps

- **Type 1** (project structure / destructive file-move) is not included due to pipeline safety concerns — moving files during automated assembly risks corrupting the working repository state.
- Documentation is generated as **structured JSON** rather than the multi-file format (specs.md, openapi_spec.yaml, etc.) described in the original project plan.
